# Політика безпеки (Security Policy)

## Підтримувані версії

Оновлення безпеки отримують лише такі версії застосунку:

| Версія | Підтримка безпеки |
| :--- | :--- |
| 1.0.x | :white_check_mark: Підтримується |
| < 1.0 | :x: Не підтримується |

---

## Повідомлення про вразливості

Команда розробки MIAUTO серйозно ставиться до безпеки даних користувачів та бізнес-інформації.

Якщо ви виявили потенційну вразливість у безпеці:
1. **НЕ створюйте** публічний issue на GitHub.
2. Надішліть приватне повідомлення або створіть [GitHub Security Advisory](https://github.com/AlexKabaiev/miauto/security/advisories/new).
3. У звіті вкажіть:
   - Детальний опис знайденої проблеми або вектора атаки;
   - Покрокову інструкцію або PoC (Proof of Concept) для відтворення;
   - Потенційний вплив (витік даних, пошкодження БД SQLite, підвищення привілеїв);
   - Вашу контактну інформацію для координації виправлення.

### Регламент відповіді
* **Первинна відповідь:** до 48 годин з моменту отримання звіту.
* **Оцінка та верифікація:** до 5 робочих днів.
* **Випуск патчу/релізу:** орієнтовно протягом 14 днів у разі підтвердження критичної вразливості.

## Запобігання витоку конфіденційних даних

1. **Секрети та ключі API:** Усі токени та зовнішні ключі (наприклад, курси валют Monobank) конфігуруються через змінні середовища та ніколи не комітяться у репозиторій.
2. **База даних:** Файли бази даних `*.db` додані до `.gitignore` та не повинні потрапляти у публічні репозиторії. Для розробки використовується генератор вигаданих даних (`py -m app.seed`).
3. **Локальна безпека:** Сервер бекенду за замовчуванням прив'язаний до локального інтерфейсу `127.0.0.1`, блокуючи неавторизований доступ із зовнішніх мереж.
